> 本文件记录用户最新提出的**产品方向与需求**。除明确标注“已实现”外，均为**未实现、仅记录**，留待后续开发。不要把这些写进“已完成”。
>
> **2026-10-21 更新：** 用户已把第一版收敛为“定时按关键词选视频取字幕 → 每个视频一条总结 → 每轮汇总 + 实体 + 日报 → 定期检查 @ → 视频不重复总结，其他功能暂时隐藏”（目标见 `docs/V1-SCOPE.md`）。该 V1 精简版**已实现**（迁移 0009，head），其中“每天固定钟点 + 时区”调度也已落地；但整条“每天固定钟点 → 发现 → 总结 → 汇总 → 日报”的**无人值守端到端仍未用真实服务验证**。

## 1. 自动化为主（部分实现，端到端未验证）

用户诉求：**不要时刻盯着系统，大多数时候以自动化为主**。希望系统每天在固定时间段自动查找信息并整合。V1 已按此收敛。

### 目标行为

- 每个关键词来源可配置“每天固定时间”（如 08:00，含时区）自动运行一次发现；
- 发现 → 采集 → 处理（每个视频一条总结）→ 每轮汇总 → 实体更新 → 日报，整条链无人值守跑通；
- 运行结果、错误、费用汇总到“任务页 / 日报 / 调用账本”，可事后回看，不在线等待。

### 现状与差距

| 能力 | 现状 | 差距 |
|---|---|---|
| 定时调度 | 已有 `app/jobs/scheduler.py`，支持“每天固定钟点 + 时区”（`discovery_sources.daily_time`/`schedule_timezone`，`next_configured_run`），间隔模式兜底 | **每天钟点已实现**；尚未用真实服务验证无人值守整链 |
| 触发条件 | 只有 `enabled AND network_authorized` 的来源才被调度 | 符合预期，保持不变 |
| 发现→采集 | `discover_keywords` → 入队 `collect_source` | 已实现（M2） |
| 采集→处理 | `simple_mode` 下 `collect_source` 完成后自动 `process_source` → `simple.summarize`（每视频一条总结） | 已实现（V1）；真实模型总结未烟测 |
| 整合 | 每轮 `finish_round` 汇总简报、更新实体、写当日日报 | 已实现（V1）；日报/摘要仍基于模型输出，未用真实模型验证 |
| 无人值守 | worker 进程内 tick，`FISHINGNET_SCHEDULER=0` 可关闭 | 失败/预算告警靠日志与账本；端到端无人值守未真实烟测 |

### 约束（必须保留）

- 自动化的网络与模型调用仍必须**逐来源/逐路由显式授权**：`enabled` 与 `network_authorized` 分离且默认 false；供应商/模型默认停用、任务路由默认未配置、预算默认 0、数据策略默认 `local_only`。
- 不因“自动化”把默认值改成 true，也不让一次勾选同时代表“启用 + 联网 + 云端”。
- 模型调用保持“预留预算→无事务 HTTP→结算”；B站 请求保持低频、可中止、记录错误码；不绕过登录/付费/验证码/风控。
- 自动化失败不能静默吞掉：要落运行账本 + 日报 + 错误码。

## 2. 实体/主题由模型建立 + 动态分组

| 项 | 状态 |
|---|---|
| 模型自动创建**实体**（entity） | **已实现**（M4 Phase 2 补充，2026-10-21）：`entity_disambiguation` 返回 `new_entities`，服务端按名称去重后自动建 `provisional` 节点，不自动合并 |
| 模型自动创建**主题**（topic） | **未实现**：当前只自动建实体，主题仍需手动创建 |
| 一个实体一条动态、多实体拆多条 | **已实现**：按（来源版本 + 实体）分组，未归类仍逐条 |
| 关联到**已有**实体 | 仍 `proposed` + 人工接受（避免错误归并） |
| 自动建的实体可复核 | 实体管理里可改名/合并/删除（`provisional`） |

## 3. 其他已记录、按用户决定推迟/未做

- 批量导入、密码恢复、语言偏好、完整 E2E（推迟）。
- `claim_comparison` 模型路由、来源画像评估、纠错表达式生成、真实模型抽取/复核/实体消歧/事实核查烟测、真实扫码/分P批量/凭证恢复/定时调度。
- 跨进程/多节点预算、Anthropic/Gemini 原生协议、供应商账单对账。

## 4. 下一步建议顺序（供下一位开发者）

1. **V1 真实验证（优先）**：在用户授权下，用固定合成材料真实执行一次“视频总结 + 每轮汇总与实体更新”（显式启用 `update_generation`/`digest_polish` 路由、预算充足，检查真实模型 JSON 能否通过服务端校验），再低频真实验证一次关键词发现/字幕/@ 通知，最后跑通“每天固定钟点 → 发现 → 总结 → 汇总 → 日报”的无人值守端到端并记录错误码与费用；
2. 补主题（topic）自动创建（当前只自动建实体）；
3. 在用户授权下做真实模型/B站 低频烟测（`claim_comparison`、`fact_check` 等历史 M4 剩余项）。
